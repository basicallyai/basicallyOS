# Shared AI knowledge workspace — architecture and boundaries

## Research and design

Before implementing the Notes surface, the official [Obsidian Help sources](https://github.com/obsidianmd/obsidian-help) were reviewed: **Internal links**, **Tabs**, **Manage vaults**, **Backlinks**, **Views and editing mode**, **Search**, and **Command palette**. Help-site HTML shells were reachable, but content endpoints returned 403; the official repository's Markdown sources supplied the actual documentation. Properties documentation informed the small frontmatter/tag index. Research copies are development logs, not distributed assets.

Functional lessons adopted: user-owned folders; multiple vaults; source versus rendered views; persistent tab groups and splits; contextual backlinks; fuzzy command discovery; and explicit ambiguity rather than guessing a note. This is an original basically OS interface. No Obsidian branding, visual assets, application code, plugins or proprietary storage is used. It is not a complete Obsidian replacement or plugin-compatible implementation.

## One runtime, multiple surfaces

- `server.mjs` creates the existing Store, Runtime and local-model worker, then adds one Resources and one Memories service.
- `runtime.mjs` still owns real Pi Agent runs, providers, tool execution, approvals, cancellation, durable transcripts and usage ledgers. There is no second chat engine, provider adapter or hidden memory model.
- Conversations carry `surface: chat | notes` and explicit `workspaceIds`. Main Chat and Notes AI have separate current-conversation/draft slots but the same conversation store. A run can continue while its surface is hidden. All completed tool follow-ups count in the same usage ledger.
- `web/knowledge.js` is a helper-injected controller, not a separate application bootstrap. Notes AI physically hosts the existing chat DOM, model picker, composer, stream renderer and approval interface.
- `web/markdown.js` is shared across chat, notes and editor previews. `web/wiki.js` supplies position-preserving reference parsing for browser and server; code fences, inline code and escaped wiki text are not references. `web/editor-text.js` preserves untouched source line endings and identifies editable tasks.

## Authorized local resources

`resources.mjs` stores library identities/grants in `app/workspaces.json`. A first-party **My Notes** library at `<private-data>/notes/` is created automatically, not imported as a project. Its stable ID survives restarts and it shares all indexing, wiki, history and revision machinery. It cannot be detached. Its fixed app-owned canonical directory/identity is re-established on startup, with symlink roots rejected; root identity is still checked for every live access. Optional external project grants are never refreshed implicitly. Attaching an existing external absolute local folder requires explicit user confirmation. Each grant records its canonical root, filesystem identity, label, project context and AI-change policy. Folder contents remain ordinary files in their original location. Detaching removes authorization, never those files.

Every resource access validates its workspace ID and conversation scope, relative portable path, authorized-root identity and path components. Traversal, absolute child paths, alternate streams, reserved Windows names, symbolic links, junctions and hard-linked files are rejected. Known private metadata/dependency directories, `.env*`, common credential files and private-key extensions are excluded. Private-root comparisons use the canonical `app/` path, including when the profile path uses a Windows short-name alias or a directory link. The private `app/` metadata directory cannot be attached or reached through an authorized parent; the separate first-party `notes/` directory is intentionally a scoped resource. These exclusions are defensive defaults, **not a guarantee that arbitrary user files contain no secrets**.

The shared index is in memory, not a second notes database. Polls compare filesystem identities and high-resolution size/mtime/ctime signatures. Existing content can be reused when signatures match. Search, wiki resolution, backlinks and tools share the index; exact resource reads and write revisions use current file bytes. Ordinary external renames within a grant can be followed by identity, including tabs and browser drafts. External tools are not authorized to trigger automatic link rewrites by this app.

Folder grants are chosen through a native OS directory picker (`folder-picker.mjs`, fixed commands with no shell interpolation) and then validated by the same resource service as before. Windows uses the standard modern `OpenFileDialog` shell picker with a folder-only filter and a placeholder filename: navigating into a folder and clicking Open yields that folder, while pasting a full deep path into the address bar or filename field selects it directly. This replaces the older tree-only folder dialog. The server derives the chosen directory from the returned path and validates it through the normal grant checks. The browser never receives or invents filesystem access from a name; it only posts the selected path for explicit confirmation. Cancellation attaches nothing. A secondary manual-path disclosure exists for Linux desktops without zenity/kdialog.

Main Chat must explicitly select libraries using its composer folder button. If a wiki reference is sent with no scope, the UI first asks permission to use My Notes; it never infers external project grants from the text. A new Notes AI conversation uses the attached folders; the active document and selection are bounded reference context. Expanding an existing conversation to an excluded active folder asks first. A model cannot attach folders, change policies or expand its own scope. Project-scoped runs omit `run_command` so it cannot serve as an unrestricted filesystem bypass. The separate private upload workspace remains available through the original tools.

### Shared project tools

- `list_resources`, `read_resource`, `search_resources`, `resolve_resource`, `resource_links`.
- `write_resource`, exact-match `edit_resource`, `move_resource`, `delete_resource`.

Tools resolve only within the run's scope. Text reads are line/character ranged and bounded. Before a mutation, the runtime prepares the same operation plan used by the editor. Default policy shows a diff and requires one-time approval. Automatic project changes require an explicit, separate per-folder opt-in; their operations remain visible and undoable. Destination folders and rewritten links are included in policy checks. Authorization, revisions and stricter policy changes are rechecked before execution.

## Editing, synchronization and recovery

Each open file has one document state shared by its visible split views: content, saved content, SHA-256 revision, source snapshots, draft and conflict state. The default Markdown editor is Tiptap/ProseMirror, locally prebundled by `editor-bundle.mjs`; Notes, Canvas, the composer and Markdown settings import the same adapter. ProseMirror owns editable DOM, selection, input rules, Markdown/rich paste, formatting commands and native undo/redo. A normal document is one rendered editable surface, not a synchronized textarea/preview pair. Optional source editing stays plain UTF-8 and non-Markdown files bypass Markdown parsing. Original BOMs and untouched CRLF/CR/LF sequences are retained; newly inserted line breaks follow the document's detected convention. Existing Unix permission modes are preserved where supported; ownership/ACL metadata is not a cross-platform preservation guarantee.

Editor transactions debounce Markdown serialization for about 120 ms; pending DOM/editor changes are explicitly flushed before save, navigation, copy, external refresh and pagehide. Formatting-only or read-only-state transactions never mark content dirty. Original top-level Markdown blocks are reused when unchanged; edited blocks serialize through Tiptap Markdown. Frontmatter, footnotes/definitions, wiki references, images and inert HTML use explicit preservation nodes. Unsupported constructs remain visible/source-editable instead of silently discarded. Authorized raster images and remote-image consent reuse the sanitized renderer. BOMs and unchanged line breaks are preserved using `editor-text.js`. Edited block syntax can be normalized; this is not a claim of universal byte-identical Markdown round-tripping.

Edits debounce an autosave after about 700 ms. Pending drafts also live in browser localStorage. A stale save never intentionally replaces a newly read external version: the user compares disk/draft and explicitly reloads or overwrites that version. Clear browser storage only after saving/exporting important drafts. Saving to original folders is a direct user edit, not a model approval event.

Mutation plans contain before/after snapshots for all affected files and directories, roots and optional moves. Unified diff previews identify both workspace and path. File versions are validated before commit and again per affected entry. An operation journal is persisted before applying changes. Individual files use atomic replacement. Successful app moves rewrite uniquely resolved wiki links in indexed UTF-8 sources, preserving aliases/fragments and updating moved-source references.

**Multi-file operations are not one atomic filesystem transaction.** On failure/startup the service attempts rollback only when the current versions match recorded before/after states. Unexpected intervening content is retained and the journal is marked `recovery-required` for inspection. Undo applies reversed snapshots as a new revision-checked operation, refusing intervening changes. It restores recorded files, not every later-created link elsewhere. File history is bounded; it is not a substitute for a vault backup or version control.

Path checks and revision checks are best-effort application protections, not an OS sandbox or protection against a hostile same-account process racing filesystem syscalls. In a non-project conversation an explicitly approved shell command still runs with the account's full filesystem/network privileges. Never approve a command or broad folder grant you do not understand.

## Wiki references and Markdown

Chat references resolve against the conversation's selected folders, optionally relative to its active file. Exact/relative paths take precedence over basename matching. Workspace IDs or labels can disambiguate a target. Aliases and heading/block fragments are parsed, code examples ignored, and ambiguous candidates require a browser choice. The server validates that choice against authorized candidates before reading. Missing references, missing sections, binary/unavailable files and excerpt budget exhaustion are represented explicitly; no path grants are inferred from wiki text.

Resolved excerpts include source, line and revision. They are user/reference data, never permission or higher-priority instructions. Providers receive bounded excerpts, not entire vaults. Further retrieval uses the same scoped tools. Conversation input metadata keeps the actual resolved references for later inspection.

One GFM renderer uses marked, DOMPurify, locally served Highlight.js and KaTeX. All four math delimiters (`$…$`, `\(…\)`, `$$…$$`, `\[…\]`) are tokenized outside code. Untrusted Markdown is sanitized first; numeric placeholder spans are then replaced by KaTeX-created DOM with `trust: false`, bounded expansion/size, HTML+MathML output and local fonts. KaTeX's programmatic styles work without relaxing the page CSP to arbitrary inline HTML styles. Expressions are limited to 20,000 characters; bounded math/highlight caches avoid repeated work. Unknown languages/very large code blocks remain exact readable source rather than forcing expensive highlighting. Raw HTML is escaped before sanitization; active HTML/SVG/iframes are not accepted. The editable Markdown model is serialized by Tiptap Markdown, never scraped from rendered preview HTML. Local raster images use authorized resource routes. Remote HTTPS images stay behind a per-image consent button and load without a referrer. External links open with `noopener noreferrer`. Wiki note embeds are navigable references, not full note transclusion. Ordinary Markdown links are navigable but are not included in wiki backlinks or automatic move rewrites.

## Model metadata and provider contracts

`model-catalog.mjs` queries the configured endpoint's live `/models` catalog. A per-model `upstreamProvider` on OpenRouter Chat Completions instead selects live `/models/{author}/{slug}/endpoints` metadata by exact endpoint tag or an unambiguous provider name. Outgoing Pi payloads carry `provider: { only: [nameOrTag], allow_fallbacks: false }`. No default-provider pricing fallback is used for a pin. Route changes clear stale rates, limits and capabilities, including old manual values; display labels remain user-owned. Late responses from a different route are discarded. Verified manual values can be entered after lookup. Other APIs must use a provider-specific connection, not an unsupported routing payload. ID editing is debounced; requests are coalesced/cached per endpoint and credential hash for 15 minutes (64 in-memory cache slots). Route-specific catalogs are cached separately per model/route. Errors back off for at least 10 seconds; 429 honors a bounded Retry-After. Responses are streamed with a 4 MB ceiling and 15-second timeout, with redirects rejected. A saved credential is reused only for its unchanged endpoint. No model catalog or price table is bundled.

OpenRouter's published model limits, modalities, supported parameters and per-token prices are normalized. Other compatible catalogs can supply explicit metadata; prices require known units. Standard OpenAI `/models` exposes identity but not pricing, context limits or configurable reasoning levels, so those fields remain unavailable rather than being inferred from names. Users can enter verified values manually. Unknown models can be saved, but verified context/output limits are required before generating. Existing/manual limits, labels, rates and overrides are preserved; a different ID clears stale model metadata. Missing cache rates remain unknown; cached usage with no applicable rate is unpriced, not silently estimated at zero or the input rate. Provider-reported actual USD still takes precedence.

## Shared layout, streaming and UI lifecycle

`web/split-layout.js` supplies accessible pointer/keyboard separators, min/max bounds, frame-coalesced style changes, double-click defaults and drag cleanup on release/cancel/window blur. Main sidebar, context/AI panel, editor split weights, conversation width and reasoning/tool output bounds use this architecture. Editor groups persist in the profile layout; browser-specific dimensions persist in local preferences. Collapse does not discard dimensions. Container/mobile layouts adapt editor groups and use overlay navigation where necessary. Reduced motion disables transitions/animations, including pseudo-elements. Startup controls are inert until initialization completes.

`web/render-dom.js` retains unchanged Markdown blocks and keyed transcript nodes, preserving selection, details state and image consent rather than replacing the full conversation on updates. Streaming work is coalesced at roughly 60 ms. `web/stream-state.js` reconciles ordered delta offsets/run IDs/revisions with concurrent HTTP snapshots: duplicate/older chunks are ignored, newer local deltas are retained over stale snapshots and gaps request a fresh snapshot. Assistant boundaries and settlement advance revisions so old text cannot reappear beside its final message. Tool arguments/metadata remain exact expandable code; Markdown content uses the shared renderer. Shutdown is idempotent.

## Notes identity, hidden extensions, and Canvas

Note identity lives in `app/note-catalog.json`, keyed by workspace + path and reconciled against filesystem identity. Files remain ordinary `.md` documents; the catalog only supplies a stable `noteId`, tracks moves, and records which equations a model actually generated. `.md`/`.markdown` are stripped in every user-facing surface (explorer, tabs, breadcrumbs, search, backlinks, rename), while ordinary non-note files keep their real names. Creation and renaming accept titles, normalise an entered extension, and open an existing note rather than overwriting a duplicate title.

`canvases.mjs` owns standalone conversation documents in `chat.canvases[]`: UUID `canvasId`, title/content/revision, timestamps, original request association, bounded history and separate presentation `uiState`. There is no small fixed document-count limit; model metadata/tool listings page at 100 documents, reads at 24,000 characters. `chat.canvas = {canvasId}` is visibility only; unrelated requests clear it without deleting documents, and dismissal during a run prevents tools from immediately reopening the view. Source/rich preference and scroll state persist separately from source revisions, with browser recovery.

Save to Notes writes a revision-checked ordinary Markdown file and replaces standalone content/history with a stable `noteId` delegation, retaining the original Canvas identity. Every linked read/write then goes through Notes/Resources: no independently editable duplicate exists. A `pendingNote` association is persisted before filesystem commit; retries/startup migration recover only if the exact recorded content matches, otherwise preserve the standalone draft and report conflict. Migration and document/user conversation mutations share a serialized queue to prevent stale-chat writes and duplicate recovery races. Note-reference Canvases from previous versions migrate into the collection without moving/deleting notes.

Pi tools create/list/open/edit/link actual documents; linked model mutations commit the exact prepared resource plan shown in the review, preserving diffs, one-time approval and policy rechecks across every changed folder (including rewritten backlinks). Public conversation metadata excludes content/history/math payloads; the document route loads the active document. Resource events refresh linked Canvas/Notes, moves follow the note catalog, and a dirty draft becomes an explicit conflict rather than being replaced. Editing pauses during an active run. Standalone snapshots retain 30 revisions / 8 MB; linked documents use file history. Exports preserve standalone artifacts with fresh IDs on import; linked associations become historical/unavailable, never live authorization.

`notes.mjs` also imports bounded batches of base64-encoded UTF-8 Markdown, preserving bytes/BOM/line endings and folder-relative paths, refusing traversal/binary/invalid encoding and safely suffixing duplicates. Each successful file is committed through Resources and indexed immediately. UI supports single/multiple files, folder pickers and directory/file drop. Bounds: 200 files, 2 MB per file, 12 MB per batch; dropped directory traversal caps at 10,000 entries / 32 levels. Failed files are disclosed.

## Web research and code/file displays

`web-search.mjs` exposes optional `web_search` / `open_webpage` tools only to opted-in conversations. Enabling the Globe is permission, never a forced search; the ordinary Pi tool policy remains automatic and the system/tool guidance explicitly permits an answer without browsing. UI uses the exact local Lucide Globe, with active colour `--reasoning-text` to match Thinking in both themes.

`browser-research.mjs` detects supported OS-installed browsers (Firefox, Chrome, Edge, Brave and Chromium) and prefers the default HTTPS handler when supported. Browser IDs/names—not executable paths, keys or personal profile paths—are exposed to the UI. Bing is the default public search engine, with DuckDuckGo selectable. `puppeteer-core` launches the selected installed binary headlessly in a disposable isolated profile. No browser download, existing-profile connection, personal cookies, extensions, history or logged-in tabs are used. Safari/unrecognized browsers are unsupported, with an explicit missing-browser error.

Local browser search is the default. **Settings → Preferences → Web browsing settings** additionally offers an opt-in Brave or Tavily API mode. API keys are never accepted from the composer/Globe flow and are never returned to the browser; `web-search.json` keeps a separate key per provider so switching providers cannot silently forward one provider's credential to another. A blank key preserves that provider's saved key; explicit removal is separate. Status exposes only booleans, browser id/name and the selected engine/provider. Configuration is serialized, validated before writing, and API mode does not require any installed browser. Local mode never falls back to a paid API on CAPTCHA, failure or missing results—the error remains explicit. Existing legacy keyed records are migrated into provider-specific credentials but default to local browser mode, requiring a deliberate settings choice before any API is used. Document extraction in API mode uses the same bounded, script-free, DNS-pinned HTTP transport rather than a browser.

Each main-document navigation is intercepted and fulfilled through `fetchPublic` with the actual browser user agent; all other page requests, frames, secondary navigations and subresources are blocked. Script/frame/object/meta-refresh source is removed and a restrictive CSP blocks site scripts (Chromium also disables page scripting directly; Firefox retains the trusted automation runtime). HTTPS/DNS/redirect validation is enforced outside the browser rather than trusting its DNS cache. Browser sessions have bounded startup/protocol/overall deadlines, run cancellation and owned-process cleanup. A Firefox initial-session handshake timeout can retry once with a fresh temporary profile before any external request. Search result links/snippets are extracted from the real engine HTML, including documented redirect-link decoding, and never filled with fabricated fallback results; verification challenges are explicit failures.

Readability + linkedom extract inert text and up to 40 follow-up links. Successful results carry source URLs/timestamps, are inspectable in collapsed tool cards and are explicitly untrusted reference data. System/tool guidance forbids treating pages as permission or memory-write instructions; this is not a guarantee of perfect model-level prompt-injection resistance.

The production transport accepts HTTPS port 443 only, blocks URL credentials and non-public/reserved IPs, resolves and pins a validated DNS address on every redirect, drops sensitive headers on redirects, caps redirects at four and response bodies at 3 MB, and applies DNS/inactivity/overall deadlines plus run cancellation. Extracted text caps at 20,000 characters. Missing keys, malformed responses, rate limits, unsupported media and inaccessible pages fail explicitly; no mock or fabricated fallback is used in production.

`web/code-display.js`, `copy-button.js` and `file-preview.js` provide shared read-only source displays, language/line-count headers and exact Copy → Check feedback (1.7 seconds, accessible failures, no success toast). Streaming reconciles the code container/copy source instead of replacing completed DOM. Highlighting is bypassed above 100,000 characters. File previews accept exact valid UTF-8 up to 20 MB, never execute HTML/JS, ignore stale preview responses, and download an immutable UTF-8 Blob snapshot so disk changes after inspection cannot alter that download. Unsupported/binary previews expose the original download route instead. The closed-sidebar toggle uses the existing brand SVG with hover/focus icon transition and reduced-motion handling.

## Agent-managed memory

`memories.mjs` keeps structured entries in `app/memories.json` alongside the existing editable `app/MEMORY.md`. Entries have stable IDs, revisions, category, tags, optional project scope, timestamps, expiry and source. Audit records contain metadata and affected IDs, not retained before/after fact bodies.

Before every new message, current memory/global/chat instructions replace historical system snapshots in the active Agent context. The retrieval layer selects bounded hybrid memories using deterministic concept expansion, weighted term overlap, scope, category, recency and a certainty penalty, with revision-keyed caching; the same agent can search, read complete entries and perform revision-checked upsert/delete/merge operations. No embedding service, separate memory LLM or hidden paid background consolidation exists. Intelligent saving/consolidation depends on the configured tool-capable model following the memory guidance; deterministic deduplication, revision/scope validation and retention checks enforce storage invariants, not semantic truth.

Past chat recall uses only user-authored `inputs[].text`, never attachment bodies, injected resource data, tool output, hidden reasoning or assistant claims. It scans all available source ages, scores matching bounded chunks with deterministic relevance times `.55 + .45 / (1 + ageDays / 60)`, then packs up to six excerpts/two per source into 4,000 serialized characters. There is no age cutoff, automatic deletion, neural embedding service or hidden inference. Prompt timestamps prevent an unrelated new turn from making an old prompt fresh. New inputs persist workspace-scope snapshots; both source chat scope and input scope must fit the destination’s current grants. Memory-off sources, historical imported project scopes and detected secrets/saved API keys are excluded. Secret detection remains heuristic. `search_chat_memory` exposes the same bounded, scope-checked search to the current model. Per-response `memorySources` records source metadata, not copied excerpts, and is inspectable from the conversation menu. A deleted saved fact can still exist in source prompts; delete/opt out that source to exclude it. Archived chats remain eligible. Context limits can exclude low-ranked material; this is not universal recall.

Modes: **review** by default; explicit **automatic** for structured updates; **off** disables automatic context retrieval and model memory tools. Complete model replacements of `MEMORY.md` always require one-time approval. Policy is rechecked for pending changes. User edits remain available when automatic memory is off.

Updates preserve an entry's project scope unless explicitly changed. A new agent memory in a single-project run defaults to that project. Multi-project creation and cross-scope consolidation require deliberate scope selection. Exact duplicates do not accumulate; consolidations require all superseded revisions. Basic secret-pattern detection is an additional model-write guard, not a secret classifier guarantee. Relevant memory is plaintext model context; never put credentials in it.

Saved facts have no expiry by default. Explicit user-selected deletion policies remain separate from chat-recall weighting. Expired managed entries are filtered immediately and physically removed at startup or on the minute timer. Removing/expiring entries does not erase facts already copied into old transcripts, backups or browser drafts. Review/delete those separately if needed.

## Honest thinking and accounting

Pi's normalized provider `thinking_delta` events and plain thinking blocks are streamed/stored separately from answer text. The public view exposes only actual reasoning text, never encrypted signatures. A collapsed/native details panel can be opened during generation and retained after settlement. If no content is exposed, only actual connecting/working/responding/tool/approval phases are shown. No synthetic chain of thought, inferred reasoning or fabricated duration is generated.

**Model quick-selection** is an anchored menu (`web/model-picker.js`), not a modal: display-name rows, current-model checkmark, optional search for long lists, no context/pricing/capability/raw-ID/provider metadata, and a separate Effort submenu containing only the selected model’s advertised levels. The submenu flips left/right to remain in the viewport; the root menu prefers opening above its trigger and falls back below. Selection, Escape, outside pointer/focus loss and arrow/Home/End/Tab navigation are handled; focus returns to the trigger. `Manage models` opens the existing settings. Reasoning controls live in that Effort submenu, not general preferences. `reasoningConfig` carries an explicitly advertised/manually confirmed format and allowed levels. `settings.reasoningOverrides` persists choices per connection/model; old general effort is only a fallback when supported. Pi-inferred reasoning fields are stripped from outgoing payloads, then only validated model-specific settings are added: OpenRouter's nested normalized reasoning object, OpenAI Completions `reasoning_effort`, or Responses `reasoning.effort`. A reasoning flag alone does not imply configurable effort. Unsupported controls remain absent; exposed provider reasoning can still be rendered without configuring effort. Providers differ in what summaries they expose. Usage accounting remains provider-reported or explicitly rate-estimated, with unknown/interrupted usage unpriced. Estimated usage entries snapshot their configured rates and upstream pin; changing future routing/prices never reprices the historical ledger or replaces provider-reported charges. Each completed assistant message snapshots its configured display name and measured output-token throughput: actual usage.output divided by monotonic request-to-completion time, not a decode-only benchmark. Missing/interrupted usage receives no invented measurement. Measurements survive history, regeneration and validated backup import/export; UI copy/note save excludes them. Native streaming now emits real prompt/completion usage. Memory/resource tool follow-ups are ordinary accounted requests. These features have no independent paid background inference.

## Persistence, backups and packaging

Private data adds `workspaces.json`, `knowledge-layout.json`, `file-history/`, `note-catalog.json`, `web-search.json` and `memories.json` to the original configuration/chats/MEMORY.md. Keys remain private local JSON, not OS-vault-encrypted. All routes, including raster assets, remain behind the existing loopback authentication, origin/Host checks and CSP.

Conversation backups retain Chat/Notes surface, original messages/reasoning/tool history, resolved-reference metadata and historical workspace bindings. Imports generate fresh chat IDs and restore no filesystem grants: historical bindings are inert metadata until the user selects authorized folders again. No imported tool call executes. Managed notes, attached vault/project files, memory libraries, settings, grants, layouts and weights are not part of a conversation backup. Back up ordinary vault folders and the private profile separately.

The npm/portable allowlists include the shared services and local web assets, not user folders, profiles, development tests/logs or weights. Only Pi Agent Core + Pi AI are used as the assistant runtime. The complete coding-agent harness/CLI/TUI is not a dependency.

## Deliberate bounds and limitations

- One managed notes library plus up to 32 attached folders; 20,000 indexed entries and 32 MB indexed text per folder; 512 KB content indexing per file; 2,000 returned directory entries. Limits/inaccessible contents are surfaced as partial search coverage. Large libraries and network drives are not performance-certified by the workflow tests.
- Editable files: valid UTF-8, at most 2 MB, no NULs. Binary/other encodings stay original and download-only. Local raster assets/downloads are capped at 20 MB.
- Reversible directory operations: up to 300 entries; 18 MB before/after snapshot bytes. History keeps up to 100 operations / 64 MB, except unresolved recovery records.
- Pending user reviews expire after five minutes, with at most 10 reviews / 64 MB of encoded snapshots. Diff computation is time-bounded and previews are capped at 100,000 characters per file; limited previews say so and model approvals expose full tool arguments for inspection.
- Up to four editor panes, 40 tabs per pane. Browser drafts depend on browser storage quota. A crashed browser cannot guarantee an unsent final keystroke was durably written.
- Chat reference context: first 20 wiki occurrences, 6,000 characters per file/section, 24,000 total excerpt characters. Active-document and selected-text context are each capped at 6,000. Tool text reads cap at 12,000 characters and 200 lines per response.
- Managed memory: 1,000 entries, 4,000 characters per entry, 200 audit records; consolidate up to 30 entries per operation. Default context: 8,000 legacy characters plus 8,000 selected managed-memory characters and 4,000 serialized history characters (six excerpts/two per source chat). Search is deterministic concept/term/scope based, not universal semantic recall.
- No full IDE language server, plugin ecosystem, universal Markdown dialect preservation, note transclusion engine, encrypted vault, collaboration server, token compaction or automatic external-link rewriting. Native local inference remains text-only without tools; it can use bounded context but cannot autonomously modify notes/memory. The load UI explicitly defaults repository-code trust on, with confirmation for detected custom code; both Transformers loaders receive `trust_remote_code=True` only for that trusted load. This executes unsandboxed Python with the user's full permissions. `.py` uploads are accepted as inert files (2 MB each), and `auto_map` declarations are inspected for missing model/tokenizer modules without importing them. No import/refresh/rename executes model code. Hugging Face loading remains local/offline; trusted repository Python can still perform arbitrary operations. No model-specific dependency auto-installation occurs. Missing templates use explicit generic role-labelled text, not guessed special tokens. Known native templates stay authoritative. Context comes from real config/tokenizer limits, capped at 32,768; the app output budget is capped by tuning/4,096/one quarter of context. Oversized prompts are left-trimmed with per-response omitted-token disclosure; this may omit instructions/memory. Missing limits are errors, not invented defaults. Token counts come from actual generation token IDs via a counting streamer, including EOS, not retokenized visible strings or SSE chunk counts. Worker completion usage and request-ID-matched context diagnostics reach the same Pi runtime. Local display names persist in `local-model-names.json` outside model files; naming never changes folder identities. Local model support is limited to complete Transformers/safetensors repositories: GGUF files, MLX manifests and their runtimes are rejected or ignored, not loaded.

## Verification

`npm test` covers actual Pi mock-provider runs, reasoning field/Responses normalization, scopes, approvals, policy modes, memory revisions/consolidation/expiry, workspace boundaries, links/moves, indexing, backups without authorization, source fidelity, journal recovery and external-change preservation. The existing tests still cover costs, cancellation, uploads, setup, authenticated routes, migrations and crash accounting.

Ubuntu CI narrowly permits browser user namespaces through an AppArmor profile for installed Edge/Chromium paths, retaining browser sandboxing and global user-namespace restrictions. This disposable-runner setup is not shipped or run on users' machines. Resource regressions cover aliased private roots and permission-complete implicit parent snapshots, so nested-write/move undo remains revision checked on Unix as well as Windows.

`npm run test:browser` runs ten workflows (original-app, knowledge, overhaul, unity, documents, editor, workspace-tools, model-menu, polish and local-models) in a real browser: attach a folder, edit/autosave notes, follow wiki/backlinks, share split state, resolve a disk conflict, preserve BOM/CRLF source, search, use Notes AI, restore layouts, manage memory, exercise thinking panels, follow external renames and check mobile/sanitized Markdown. `npm run test:package` packs, globally installs and starts the real tarball, then executes it through offline npx and verifies the new assets/APIs. No paid provider or real-weight inference validation is implied by mock/synthetic checks. The overhaul browser workflow additionally verifies no-attachment notes; all four math syntaxes and real fraction geometry; automatic model-ID metadata and unknown fields; cached catalog requests; per-model reasoning controls and actual Pi payloads; unchanged completed streaming blocks; Markdown tool results; draggable/keyboard/reset/persisted panels; and reduced-motion/mobile behavior.
